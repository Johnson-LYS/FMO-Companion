# 计划 0008：0.6 APRS 消息与远控

## 目标

在不改变 0.4 已验收只读边界的前提下，为用户提供 App 前台活跃期间的标准 APRS 消息、ACK 和 FMO 公网远控。0.6 分两段交付：先完成消息闭环，再完成 `NORMAL / STANDBY / REBOOT`。

## 已冻结产品范围

- App 独立 `呼号-SSID` 作为消息身份；手动身份优先，收藏呼号作为常用联系人，也允许手动完整地址。
- 消息历史仅存本机并在重启后恢复；支持系统左滑删除，不云同步、不自动清理。
- 普通消息首次发送后最多自动重试 2 次；后台、身份变化或重试耗尽立即停止，旧消息不自动补发。
- 消息状态为发送中、等待 ACK、已确认、未确认；重复消息只展示一次但仍响应 ACK。
- APRS-IS PASSCODE 由规范化基础呼号按公开算法自动计算，SSID 不参与，用户无需输入且不持久化；按目标 FMO 隔离的 SECRET 只进入设备远控设置与 Keychain。
- `NORMAL`、`STANDBY` 单次发送；`REBOOT` 危险确认后调用 LocalAuthentication。所有远控禁止自动重发。
- 远控界面只显示目标、影响、发送阶段与确认结果，不显示 Time Slot、Counter、HMAC 或 Keychain。

## 明确排除

- 后台常驻 APRS-IS、离线消息保证、APNs、通知服务端、云存档与跨设备历史。
- 群聊、广播消息、附件、已读回执和在线状态推断。
- 自动位置上报或任意 APRS 数据帧；0.6 只开放标准消息、ACK 与三种官方远控。
- 远控自动重试、其他控制命令及局域网 `/ws` 配置写操作。
- QSO、自建服务器运维、实时活动和 1.0 系统集成。

## 协议冻结门槛

开发编解码器前必须固定并记录官方 APRS 消息规范和 FMO APRS Remote Control Tool 的具体版本，使用人工脱敏向量逐字节确认：

- APRS 收件地址填充、字符集、正文上限、消息 ID、`ack/rej` 与接收过滤器。
- APRS-IS 可发送登录接受/拒绝响应、公开 PASSCODE 已知向量与同呼号多会话行为。
- FMO Time Slot、Counter 位宽/作用域、HMAC 输入与截断、目标地址、命令帧及 ACK 关联。
- 官方示例代码许可证；若不允许复用，只按公开格式独立实现。

在门槛关闭前允许建立协议接口、状态机和测试替身，不允许实现推测性报文。

## 完成定义

- 用户在 App 前台可从收藏或手动地址建立会话，发送消息并看到准确 ACK/未确认状态；历史重启后保留且可安全删除。
- 前后台、断网、重复消息、迟到 ACK、登录拒绝和重启不会造成静默补发、错误确认或秘密泄露。
- 三种远控逐字节匹配官方固定向量，Counter 不复用，REBOOT 经过系统认证，任何命令都不自动重发。
- 原型、规格、实现、测试与真机行为一致，0.4 只读 FMO 网络无回归。
