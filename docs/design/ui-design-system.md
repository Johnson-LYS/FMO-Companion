# FMO Companion UI 设计方案

## 1. 目标与原则

FMO Companion 面向持证业余无线电用户，核心体验不是“展示很多无线电数据”，而是让用户随时知道三件事：当前连接是否可信、最近一次操作是否成功、出现问题时下一步做什么。

设计遵循以下原则：

1. **状态优先：** 页面第一视口先呈现设备、连接或任务状态，再呈现数据与设置。
2. **主动授权：** 在系统权限弹窗前解释用途，位置同步与危险命令必须由用户主动触发。
3. **错误可行动：** 不使用笼统的“连接失败”，明确区分 Wi-Fi、主机解析、HTTP、WebSocket 与超时。
4. **专业但不晦涩：** 保留呼号、APRS、GEO、ACK 等领域术语，同时用短说明解释结果。
5. **品牌克制：** `#FF8800` 是主操作与关键状态色，不作为大段正文或全屏背景的默认色。
6. **系统行为优先：** 正式实现使用 SwiftUI 系统导航、控件、材质、动态字体和反馈能力，品牌样式建立在系统行为之上。
7. **数据与图标优先：** 删除能从页面上下文、数值单位或图标直接推断的标签和说明。呼号、服务器名与关键值优先形成视觉层级；`GEO 会话`、`公开局域网接口`、`由 FMO 坐标换算` 等实现解释不进入主界面，`Maidenhead` 可简写为标准网格值或以网格图标表达。只有图标存在歧义、错误需要行动或操作具有风险时才增加短文案。
8. **产品结果优先于实现来源：** 用户文案回答“当前能做什么、需要我做什么”，不解释数据如何继承、协议如何登录或客户端订阅了什么。`从上次 FMO 继承`、`pass -1`、`仅订阅 FMO V4` 等规则只进入实现文档、诊断或帮助；正常界面直接呈现已经填好的值、可编辑控件与“正在接收”等结果状态。页面标题已经表达语义时，不再用无操作、无独立状态的 Hero 卡重复标题。
9. **轻量编辑不增加导航层：** 对当前上下文内少量字段的查看和编辑，优先使用底部 Sheet，保存或取消后回到原位置。两个强关联且都很短的配置可以使用 iOS 原生的第二层 Sheet，关闭后恢复第一层；嵌套最多两层，不继续套娃。字段较多、需要持续浏览或包含完整任务流程时才进入新页面。

精简视觉文案不等于删除语义：所有仅图标、缩写或上下文表达的内容必须提供完整 VoiceOver 标签、提示和值；状态不得只靠颜色区分。领域内公认缩写可以用于视觉层，首次学习成本较高或可能误操作的概念仍应在详情、帮助或辅助功能中给出全称。

## 2. 视觉方向

视觉关键词：**可靠、清晰、移动现场、精密工具**。

- 浅色模式以暖灰背景和白色信息卡为基础，减少长时间查看的眩光。
- 深色模式使用近黑中性色，不使用纯黑与大面积高饱和橙色对撞。
- 圆角用于表达可触达的功能单元；协议数据、诊断和坐标保持清晰的网格与等宽数字节奏。
- 页面避免传统后台式密集表格，优先使用摘要、状态卡、分组列表和按需展开的诊断详情。

## 3. 色彩系统

### 3.1 核心颜色

| Token | 浅色值 | 深色值 | 用途 |
|---|---:|---:|---|
| `brandPrimary` | `#FF8800` | `#FF9B2F` | 主按钮、选中态、同步中状态、品牌强调 |
| `brandPressed` | `#D96500` | `#FFAD4D` | 按下反馈或深色模式强调文字 |
| `brandText` | `#8A4300` | `#FFAD4D` | 浅色/深色背景上的橙系文字 |
| `brandTint` | `#FFF3E6` | `#3B2814` | 轻量标签、选中容器、图标底色 |
| `inkPrimary` | `#101114` | `#F7F7F2` | 正文和标题 |
| `inkSecondary` | `#5F6066` | `#B6B6BA` | 说明文字 |
| `canvas` | `#F6F6F3` | `#111215` | 页面背景 |
| `surface` | `#FFFFFF` | `#1D1E22` | 卡片和列表 |
| `success` | `#21A366` | `#4FC184` | 已连接、已验证、成功 |
| `danger` | `#D63B32` | `#FF6961` | 设备拒绝、危险操作、失败 |

### 3.2 对比度约束

- `#FF8800` 与白色的对比度约为 `2.39:1`，**不得**用作白底正文文字，也不使用白字橙底的普通按钮组合。
- 主橙色按钮使用 `#101114` 文字，对比度约为 `7.89:1`。
- 白底橙系文字使用 `#8A4300`，对比度约为 `7.28:1`。
- 状态不得仅靠颜色表达；同步显示图标、文案或形状。

## 4. 字体与数字

正式 App 使用系统字体并支持动态字体，不绑定私有字体文件。

| 层级 | SwiftUI 建议 | 用途 |
|---|---|---|
| 页面标题 | `.largeTitle.weight(.bold)` | 顶层页面名称 |
| 卡片标题 | `.title3.weight(.semibold)` | 设备、坐标与模块标题 |
| 正文 | `.body` | 说明与操作结果 |
| 次要信息 | `.subheadline` / `.footnote` | 端点、时间、数据年龄 |
| 状态标签 | `.caption.weight(.semibold)` | 已连接、规划中、已验证 |

坐标、端口、时间和计数器使用 `.monospacedDigit()`，但不把整段正文改成等宽字体。

## 5. 间距、尺寸与圆角

采用 4 点基础网格：

- 页面水平安全间距：`16 pt`。
- 卡片内部间距：`16–20 pt`。
- 关联元素间距：`8 pt`；区块间距：`16–24 pt`。
- 最小触控区域：`44 × 44 pt`。
- 主卡片圆角：`24–28 pt`；普通卡片：`16–20 pt`；标签：胶囊形。
- 分割线优先使用系统 separator，不用阴影制造每一层层级。

## 6. 信息架构

底部导航固定为四个顶层区域，默认界面只呈现用户任务，不承担需求目录职责：

| 标签 | 核心内容 |
|---|---|---|
| 设备 | 设备发现、连接、设备仪表盘、GEO 坐标、定位模式、诊断与设备远控 |
| FMO 网络 | APRS 地图、台站、事件流、消息与 ACK |
| QSO | 当前 FMO 自动同步、离线日志、查询、网格地图与 ADIF |
| 设置 | 通知、外观、服务器管理、系统集成、隐私与关于 |

FMO APRS 的证书链、签名、CRL 与可信等级当前仅作为内部准入，不提供用户入口；自建服务器运维只在用户配置管理员身份后出现在设置中。规格编号、里程碑和规划状态不进入正式用户界面。

### 6.1 原型与实现说明分离

- **可见原型：** 只呈现接近最终 App 的用户界面，默认简单、按任务组织。
- **AI 实现说明：** 规格覆盖、状态分支和 SwiftUI 映射记录在 `docs/design/prototype-implementation-guide.md` 与覆盖矩阵中。

不得在可见原型或正式 App 中加入规格跳转、里程碑、覆盖率、调试按钮或评审面板。

## 7. 0.1 核心流程

```text
权限用途说明
→ 自动发现或手动地址
→ 选择设备并连接
→ 展示盒子坐标与 iPhone 坐标
→ 用户主动点击同步
→ 显示成功、设备拒绝、连接错误或 5 秒超时
```

### 7.1 首次权限

- 首次进入先展示应用内说明，不连续触发多个系统弹窗。
- 本地网络权限在用户开始发现时申请。
- 使用期间定位在用户准备读取 iPhone 坐标时申请。
- 拒绝后提供原因、受影响能力和系统设置入口。

### 7.1.1 模式切换确认

- 自动同步模式切换使用居中的系统确认弹窗，展示模式阈值、授权要求和耗电影响。
- 不使用带锚点箭头的 Popover 或 `confirmationDialog`，避免弹出位置与实际所选条目不一致。
- 弹窗必须提供明确的启用动作与取消动作；选择当前模式时不重复弹出。

### 7.2 设备页

第一视口由三层组成：

1. 连接状态主卡：未连接、发现中、待连接、已连接或需处理；连接成功后原位展开设备仪表盘。
2. 坐标同步卡：仅在连接成功后出现，避免提前展示不可用操作。
3. 连接诊断入口：始终可见。

设备列表不在设备页常驻。连接态呼号右侧放置唯一的设备选择按钮，按钮同时表达当前设备与连接状态，点击后从底部打开设备选择 Sheet；未连接态的主操作也打开同一 Sheet。扫描结果、当前设备、手动地址和切换操作统一放在 Sheet 中。

App 启动即自动扫描并优先连接上一次成功连接的稳定设备端点。恢复失败时保留该设备和扫描结果，但不静默切换到其他设备；没有上次设备时，由用户从选择 Sheet 中连接。扫描继续增量合并结果，不让已保存或手动输入的设备突然消失。同一主机与端口只显示一项。已有连接时扫描不触发切换；用户点击其他设备行完成手动切换，点击当前设备不重连。

设备页和设备卡不提供“断开连接”按钮、菜单或 VoiceOver 动作。设备行向左滑动显示尾部“删除”操作，删除需要二次确认，并说明附近设备可能在下一次发现时重新出现；删除当前设备仍会结束连接，但列表中的其他设备不自动接管。停止扫描只结束发现任务，不影响已有连接。

### 7.2.1 连接后设备仪表盘

- 设备页顶部仍然只有一张主卡，不在下方新增第二套“状态中心”。连接成功后，发现说明原位切换为完整设备仪表盘。
- HTML 原型以 0.3 已确认字段语义为准；正式 App 采用渐进披露，只渲染当前有可信且获准来源的字段。延期字段不使用固定示例、`0` 或 `--` 填满版式。
- 卡片只保留三个内容区域且不嵌套成多张小卡：第一层以无前置图标的大字号呼号作为视觉锚点，六位梅登黑德和过滤距离紧贴其下；这两个辅助信息使用小号固定尺寸图标，图标不得高于数值文字或成为视觉主角。第二层显示无前置图标的当前服务器名称；第三层是单行动态事件窗口。服务器名称与动态事件共同置于一个大圆角容器内，不再各自套胶囊，也不使用内部横线或竖线。区域名称属于设计语义，不必作为可见标题重复出现。
- 设备页不显示经纬度、QSO 日志数或 `getUserPhyFreq` 单一频率；后两项仍可保留在类型化数据层或对应功能页，不能为了填满卡片重新加入。管理员呼号只有在取得可靠字段时才附在服务器名称下方，否则整行不存在；延迟和在线/最大人数继续隐藏。
- 字段必须能够独立显示可用、未知、过期、不支持或已拒绝。网络失败时日志数不得显示为 `0`，过期缓存不得继续使用绿色在线状态。
- 动态事件固定为单行窗口，而不是让整张卡滚动；只有说话人呼号变化时，新说话人从下方进入、旧说话人向上退出。相同呼号从讲话切换为最近活动时，整行位置保持不动，只替换固定槽位内的图标，并让呼号颜色平滑过渡为次要灰阶；图标切换不得推动呼号和时间横向位移。减少动态效果开启时退化为淡入淡出。0.4 APRS `VOCAL/CQ/STATION` 在正式接入前不冒充 0.3 本地事件。
- 当前讲话在 `/events` 健康且状态新鲜时固定优先，使用 `speaker.wave.2.fill` 或 `radio.fill`、呼号、可选网格和时间表达，不重复堆叠“通联中”“对方正在发言”等短文案；辅助功能标签为“当前讲话”。讲话结束后，最近活动使用不同图标与“最近讲话活动”语义；相对时间由系统时间视图持续刷新，不依赖新的网络事件才更新。
- 仪表盘卡片只保留一个常驻操作：呼号同一行右侧的设备选择按钮。按钮视觉层固定为单行“绿色状态点 + 当前设备名 + 下箭头”，不重复显示第二行“已连接”；完整连接语义保留在 VoiceOver 中。按钮只负责打开选择 Sheet，不承担断开或诊断；连接诊断仍作为卡片外独立入口。
- 深色仪表盘卡内的呼号、设备名、服务器名和动态主值必须使用显式浅色前景，不能继承浅色模式的系统深色文字；次要值使用带透明度的白色，确保两种外观下均有稳定对比度。

### 7.2.2 实时活动（延期）

- 实时活动不属于 0.3 交付范围，HTML 原型、设备页和设置均不展示入口。
- 已有 ActivityKit 探索实现只作为后续 checkpoint，不得以其存在认定功能已交付。
- 后续重新进入设计与开发前，必须单独确认系统权限、启动方式、锁屏信息密度和真机生命周期；不得挤占 0.3 设备卡空间。

### 7.2.3 列表删除规范

- 所有后续支持删除或移除的列表条目，默认使用系统 `List` 的尾部 `.swipeActions`，用户向左滑动后显示红色破坏性操作。
- 单一“删除”滑动按钮只显示垃圾桶图标，不重复显示文字；必须保留“删除”辅助功能标签。颜色显式使用系统危险色，不继承品牌主题色。
- 不为了单一删除动作常驻垃圾桶、`…` 或额外尾部按钮；尾部空间优先保留状态和层级提示。
- 需要二次确认的删除使用 `allowsFullSwipe: false`，避免完整滑动绕过确认；确认文案说明删除对象、影响和是否可重新发现/恢复。
- 同一操作同时提供 VoiceOver 自定义动作；长按上下文菜单可作为不改变视觉密度的替代入口。
- 只有当同一条目还包含多个高频操作时，才使用常驻“更多”入口，并在设计评审中说明原因。

### 7.3 诊断

诊断使用自下而上的半屏 Sheet，按依赖顺序显示：

1. Wi-Fi / 可用网络。
2. 主机名或 IP 解析。
3. 官方 HTTP 后台可达性。
4. GEO WebSocket 握手与响应。

诊断页先独立显示“App 连接状态”，再显示上述网络探测。探测全部通过只表示目标在当前网络路径上可达；设备页未连接时必须直接说明“不代表设备页已建立连接”，不得以四个绿勾暗示已连接。

报告默认脱敏，不包含精确位置、PASSCODE、SECRET、服务器令牌或 QSO 内容。

### 7.4 位置自动化与官方页面

- “设备功能”将位置自动化、管理后台、QSO 页面和远控作为并列任务入口，不加入评审或规格说明层。
- 模式选择直接展示手动、低功耗和车载的结果与功耗差异；自动模式在系统权限请求前二次说明固定阈值及“始终”定位要求。
- 自动模式页面始终显示授权、运行/暂停原因、最后尝试、最后成功和危险色停止操作；授权不足时不得显示为正在后台运行。
- 官方页面入口从当前或已保存设备构造，缺少设备时给出可行动提示；页面统一交给系统 Safari 界面，不在 App 内模拟网页控件。

### 7.5 收藏呼号与服务器

- 用户文案使用“收藏呼号”和“收藏服务器”，不称“收藏联系人”；消息页可把收藏呼号作为常用联系人显示，但不创建第二套数据。
- 收藏只在“FMO 网络 → 台站与服务器目录”管理。目录保留“台站 / 服务器 / 收藏”分段，收藏页再按呼号和服务器分组。
- 列表整行用于进入详情，星标是独立的非破坏性操作，最小触控区域 `44 pt`，具有“收藏/取消收藏”标签和 `isSelected` 状态；无需二次确认。
- FMO 网络页和事件流只消费收藏集合做过滤或强调，不再创建另一套收藏入口。0.3 设备仪表盘不放星标；以后点击服务器状态组进入服务器详情。
- 收藏不改变内部验证结果。收藏对象未在当前快照中出现时保留星标并显示“当前未收到数据”；技术信任状态当前不进入用户界面。
- FMO 网络身份条和未配置身份入口使用 `secondarySystemGroupedBackground` 语义卡片底色，并辅以低对比度 separator 描边；不得使用在浅色 grouped background 上近乎透明的层级背景，也不得固定写死白色破坏深色模式。
- 网络地图左下角放紧凑的“追踪”开关，右下角只放圆形定位按钮，避免两个控制挤在同侧。追踪开关必须是真实可访问 Toggle；定位按钮使用 `location.fill`，定位成功后显示独立蓝色本机标记，不复用主题色台站标记。
- FMO 网络的范围过滤使用大标题导航栏右侧的系统 Menu，不再占用地图内容区；按钮直接显示“全网”或当前公里档位，不附加通用筛选图标。使用 `.topBarTrailing` 与系统大标题模式，让它随导航栏滚动折叠，不手写滚动阈值或重复按钮。默认 `500 km`，有限范围以手机位置为中心；首次定位失败时回退全网，避免标签与内容不一致。最近动态标题旁用时钟图标与 `24h · 200` 紧凑表达保留边界，辅助功能使用完整语义。

### 7.6 APRS 消息与设备远控

- 消息入口位于“FMO 网络”，设备页不新增通讯入口。消息页先显示前台收发状态和最近会话，再提供“新消息”；不以两条聊天气泡冒充会话列表。
- 新消息 Sheet 同时提供收藏呼号和手动 `呼号-SSID` 输入。收藏按基础呼号管理，但进入会话前必须显示并允许确认实际完整地址。
- 会话气泡只显示内容、时间和产品状态：发送中、等待 ACK、已确认、未确认。不得把消息 ID、重试计数或 APRS-IS 路由常驻显示给普通用户。
- 会话左滑删除遵守全局危险操作规范，只删除本地历史；发送按钮在前台写会话未就绪时禁用并以短状态说明恢复路径。
- APRS 身份 Sheet 只保留呼号与 SSID，不增加“消息设置”或第二层 Sheet；APRS-IS PASSCODE 由基础呼号自动派生且不持久化。远控及其目标 SECRET 归属“设备 → 远程控制 → 远控设置”，不得在 FMO 网络重复出现或回显保存值。
- 远控页第一视口显示目标 FMO 和当前可用性，其次是 `NORMAL`、`STANDBY`、`REBOOT` 三个产品操作，最后显示发送/ACK 结果。移除 Time Slot、Counter、HMAC、Keychain 等技术状态卡。
- `NORMAL`、`STANDBY` 是清晰的单次发送；`REBOOT` 使用危险色确认并接系统生物认证。远控 ACK 超时显示“未确认，设备可能已经执行”，不得显示为确定失败，也不得自动重发。

### 7.7 QSO 自动同步

- QSO 标签打开即展示当前所选 FMO 的缓存与同步状态，不先展示文件导入门槛。顶部紧凑同步条使用“设备名 + 最后同步时间 + 刷新图标”，离线时改为“显示上次同步”，不出现 WebSocket、SQLite、Schema 或验签术语。
- 统计卡只使用已同步记录可计算的数量与时间范围；不显示“已验证/待检查”。列表不以勾号冒充签名结论，也不显示接口没有提供的通联时长。
- 最近通联行以对端呼号为主，服务器或网格为次，时间在尾部；整行进入详情。刷新按钮使用系统 `arrow.clockwise`，同步中保持固定触控尺寸并显示进度，避免文字抖动。
- 无当前设备时提供“前往设备”主操作；从未同步、同步中、FMO 无日志、离线缓存、部分失败和完全失败分别设计，不用空白列表表达错误。
- 搜索覆盖呼号、日期、网格和已取得详情的服务器；筛选只使用“全部 / 本月 / 有位置”等真实维度，不提供“已验证 / 待检查”。
- 详情显示双方呼号/网格、时间、频率、模式、服务器、管理员和备注中的可用字段。网格地图表达 Maidenhead 大致区域，不绘制精确轨迹；字段缺失时整行省略，不用 `--` 填满。
- ADIF 导出属于 QSO 导航栈；若缺少旧记录详情，以单一进度页补齐并允许取消。用户只看到“准备导出”和记录数量，不暴露逐条 WebSocket 请求。
- 用户切换 FMO 后，QSO 标签切换到对应设备缓存。不同设备的记录不得混合成一个总数；普通界面不提供 QSO 删除、恢复或盒子日志清空操作。

## 8. 核心组件

| 组件 | 变体 | 规则 |
|---|---|---|
| `StatusHeroCard` | idle / searching / connected / error | 每个状态包含标题、说明和唯一主操作 |
| `DeviceDashboardCard` | live / partial / stale / disconnected | 连接后承载完整设备快照；每个字段独立表达来源和过期状态 |
| `PrimaryButton` | enabled / pressed / loading / disabled | 橙底深色字；加载时保留原按钮宽度 |
| `DeviceRow` | discovered / selected / unavailable | 主体整行连接；左滑删除，显示名称、端点、来源和连接状态 |
| `CoordinateCard` | ready / syncing / success / failure | 清楚区分盒子与手机坐标，使用等宽数字 |
| `DiagnosticStep` | waiting / pass / fail | 同时使用图标、文案和颜色 |
| `PermissionExplainer` | local network / location | 先说明用途，再触发系统请求 |
| `DangerConfirmation` | remote control / server write | 解释影响，正式版接 LocalAuthentication |
| `ConversationRow` | active / acknowledged / unconfirmed | 整行进入会话；显示完整地址、摘要、时间和未读/状态，不显示协议字段 |
| `MessageBubble` | incoming / sending / waiting / acknowledged / unconfirmed | 状态由文字与图标共同表达；长内容允许纵向增长 |
| `RemoteTargetCard` | ready / missing credential / offline | 只显示目标身份和可行动状态，不展示加密实现 |

## 9. 状态文案

文案采用“结果 + 原因/下一步”结构：

- 成功：`坐标已同步` / `FMO 已更新为当前 iPhone 位置`。
- 超时：`设备没有在 5 秒内响应` / `确认盒子仍在同一 Wi‑Fi 后重试`。
- 解析失败：`无法解析 fmo.local` / `尝试手动输入盒子的 IPv4 地址`。
- 权限拒绝：`本地网络访问已关闭` / `前往系统设置允许后再发现设备`。
- 危险操作：`确认重启 FMO？` / `连接会暂时中断，正式版需生物认证`。

禁止把底层错误字符串直接显示给用户；诊断详情可提供稳定的错误分类和脱敏技术信息。

## 10. 动效与反馈

- 页面切换与 Sheet 使用系统转场。
- 设备发现可用低频扩散环提示工作中，不能用无限快速旋转制造焦虑。
- 同步按钮显示进行中状态，成功后通过触觉反馈与短暂 Toast 确认。
- 尊重“减少动态效果”；关闭非必要缩放和循环动画。
- 任何动画都不能延迟错误文案或阻止取消。

## 11. 深色模式

- 使用语义 Token 切换，不在页面内硬编码第二套颜色判断。
- 品牌橙在深色环境稍微提亮，保持主按钮的深色文字。
- 地图和诊断卡保持足够边界，不依赖阴影区分层级。
- 用户可在“浅色 / 深色 / 系统”之间选择；默认跟随系统。

## 12. 可访问性与本地化

- 支持 Dynamic Type；信息卡应允许纵向增长，不固定正文高度。
- 所有图标按钮提供可读标签；连接状态通过 VoiceOver 主动播报变化。
- 主要按钮和底部标签保持至少 `44 pt` 触控区。
- 视觉上表现为整行条目或卡片的 `Button` / `NavigationLink` 必须让包括留白、`Spacer` 和内边距在内的整行参与命中测试；SwiftUI 自定义行使用全宽 frame 与矩形 `contentShape`，不能只让图标、文字或箭头响应。
- 可删除列表条目除原生左滑操作外，还必须暴露可读的 VoiceOver 删除动作；不能让辅助功能用户依赖手势猜测。
- 颜色、图标和文案共同表达成功/失败。
- 坐标应作为一个语义组朗读，不让 VoiceOver 逐字符拆分。
- 支持简体中文作为当前原型文案；正式实现全部用户可见字符串进入 String Catalog。
- 长呼号、较大字体和英文环境下，列表尾部信息允许换行或移到第二行。

## 13. SwiftUI 实现映射

| 原型概念 | SwiftUI 建议 |
|---|---|
| 四个顶层区域 | `TabView`，每个标签内使用独立 `NavigationStack` |
| 权限与诊断 | `.sheet` / 系统权限弹窗；诊断内容使用可测试 ViewModel |
| 连接状态 | 明确的状态枚举驱动 UI，不以字符串或多个 Boolean 组合 |
| 设备仪表盘 | `DashboardSnapshot` 生成设备页白名单投影；实时活动延期，不参与 0.3 状态流 |
| 设计 Token | `Color`、间距和圆角集中定义；Feature 不硬编码品牌色 |
| 加载与取消 | `Task` 生命周期绑定 View，并支持取消 |
| 通知反馈 | `sensoryFeedback` 与可访问性播报 |
| 深色模式 | 语义颜色资产与系统环境，避免手动反转颜色 |

原型中的浏览器弹层、定时器和虚构数据只用于评审交互，不能直接复制为正式网络或权限实现。

## 14. 原型覆盖范围

HTML 原型位于 `prototype/`，覆盖 SPEC-001 至 SPEC-014。详细映射见 `docs/design/prototype-coverage-matrix.md`，主要页面包括：

- 0.1 首次权限、发现、手动地址、连接、坐标读取/同步和诊断闭环。
- 0.2 三种定位模式、节流、后台授权、断线恢复和官方 Web 入口。
- 0.3 启动恢复上次设备、设备选择 Sheet、连接后设备仪表盘与本地当前讲话/近期活动。
- 0.4 网络地图、台站与服务器目录、普通台站详情和完整事件流；FMO V4 信任验证仅在内部。
- 0.6 APRS 凭据、会话列表、收件人选择、消息/ACK、前台/离线状态和产品化远控确认。
- 0.8 当前 FMO 自动同步、离线缓存、查询详情、网格地图和 ADIF 导出。
- 1.0 自建服务器运维、管理员操作、通知、小组件、快捷指令、隐私与无障碍。

所有设备、呼号、消息、坐标和服务器信息均为虚构展示数据；原型不会访问网络、定位、Keychain 或真实 FMO。

## 15. 设计验收清单

- [ ] 0.1 主流程在不阅读说明文档的情况下可完成。
- [ ] 自动发现失败时，手动地址入口在同一层级可见。
- [ ] 用户能区分发现、连接、读取、同步和诊断状态。
- [ ] 再次发现不清除手动或已保存设备，设备可通过原生左滑删除且没有仅用于删除的常驻图标。
- [ ] 用户能区分设备页连接会话与诊断页的独立可达性结果。
- [ ] 连接后设备页原位展示完整设备仪表盘，呼号右侧设备按钮可打开选择 Sheet。
- [ ] 启动优先恢复上次成功连接的设备；恢复失败不静默切换其他设备。
- [ ] 失败状态包含下一步操作，不只有错误码。
- [ ] 主题色不承担正文文本，主按钮达到可读对比度。
- [ ] 深色模式、Dynamic Type、VoiceOver 和减少动态效果纳入实现验收。
- [ ] 所有可交互整行条目的留白区域均可点击，最小触控高度不低于 `44 pt`。
- [ ] 可见原型不包含规格编号、里程碑、覆盖率或评审工具。
- [ ] SPEC-001 至 SPEC-014 均可从四个顶层区域进入代表性流程，并在实现指南中完整映射。
- [ ] 正式 SwiftUI 代码不复制原型中的模拟网络、权限或定位逻辑。
- [ ] 0.6 消息入口能完成“选收件人 → 发送 → 等待 ACK → 已确认/未确认”，并可区分前台在线与离线状态。
- [ ] 远控页不暴露 Time Slot、Counter、HMAC 或 Keychain；REBOOT 有危险确认，所有命令 ACK 超时均不自动重发。
- [ ] QSO 无文件导入门槛；同步条、离线缓存、空状态、真实字段详情与 ADIF 流程均可评审，且不显示虚构验签或通联时长。
