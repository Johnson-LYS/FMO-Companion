# 产品规格

## 愿景

让 iPhone 成为 FMO 盒子的可靠原生伴侣：在局域网内自动发现设备并同步位置，在互联网侧安全查看 FMO/APRS 网络、发送标准消息与远控命令、管理通联日志和自建服务器，同时保持设备身份与未公开语音协议的安全边界。

## 用户画像

- **主要用户：** 已取得业余无线电操作证、呼号，并持有已激活 FMO 盒子的 iPhone 用户。
- **服务器管理员：** 自行部署 EMQX 与 FMO SAS，希望移动查看服务状态的用户。
- **移动/车载用户：** 将手机与 FMO 接入同一普通 Wi-Fi 或便携路由器，需要持续同步位置的用户。

## 功能需求

### 局域网设备

#### SPEC-001：发现 FMO 盒子

**优先级：** Must
**状态：** Approved

App 启动后应自动使用 Bonjour 浏览 `_http._tcp.local.`，识别 FMO 服务并解析可连接地址，同时提供手动主机名/IP 作为回退。扫描开始时若没有活动连接，第一台有效 FMO 自动连接一次；该候选失败后不再自动尝试本次扫描中的其他设备。

**验收标准：**

- [ ] 同一普通 Wi-Fi 中存在 FMO 时，用户可在 10 秒内看到发现结果或明确的超时状态。
- [ ] App 启动即开始一次扫描；扫描开始时没有连接或连接任务，首个本次发现的有效端点恰好触发一次自动连接。
- [ ] 首台自动连接失败后端点保留、扫描继续，但本次扫描不自动尝试第二台；用户可从列表手动选择。
- [ ] 已有连接时再次扫描只增量合并设备列表，不中断或自动切换当前设备。
- [ ] 自动发现失败时，用户可输入 `fmo.local` 或 IPv4 地址继续。
- [ ] App 记住用户选定的设备，但不保存 Wi-Fi 密码。
- [ ] 再次自动发现时，App 保留用户手动输入和已经保存的端点，并按稳定的主机与端口身份去重。
- [ ] 用户可移除设备；若移除当前设备，App 同时断开连接并清除保存记录，仍在附近的设备可在后续发现中重新出现。
- [ ] 首页不提供可见或无障碍“断开连接”操作；点击当前设备不重连，点击其他设备切换目标。停止扫描不影响已有连接。
- [ ] 本地网络权限被拒绝时，App 解释原因并提供系统设置入口。

#### SPEC-002：连接诊断

**优先级：** Must
**状态：** Approved

App 应分别诊断主机解析、HTTP 后台和 GEO WebSocket，并显示可行动的错误。

**验收标准：**

- [ ] 用户能区分未连接 Wi-Fi、无法解析主机、HTTP 不可达、WebSocket 握手失败和响应超时。
- [ ] 诊断明确区分 App 当前会话连接状态与独立可达性探测；探测全部通过不得被表述为首页已建立连接。
- [ ] 诊断报告默认脱敏，不包含精确位置、PASSCODE、SECRET 或服务器令牌。

#### SPEC-003：读取与写入坐标

**优先级：** Must
**状态：** Approved

App 应通过 `ws://<host>/ws` 实现 `getCordinate` 与 `setCordinate`，保留协议历史拼写。

**验收标准：**

- [ ] 能解析 `getCordinateResponse` 并显示盒子坐标。
- [ ] 能获取 iPhone WGS84 坐标并发送 `setCordinate`。
- [ ] 经度、纬度越界时在发送前拒绝。
- [ ] 成功、设备拒绝、连接错误和 5 秒响应超时具有不同结果。

#### SPEC-004：后台位置同步

**优先级：** Must
**状态：** Approved

App 应提供手动、低功耗和车载定位模式。后台发送由 Core Location 事件触发，再应用时间与距离阈值，不承诺严格周期。

**验收标准：**

- [ ] 手动模式不响应后台位置事件自动发送，只在用户显式操作时执行一次坐标同步。
- [ ] 低功耗模式采用固定预设：首次有效位置事件立即同步；后续相对最后一次成功同步达到 15 分钟或移动 1 公里时同步。
- [ ] 车载模式采用固定预设：首次有效位置事件立即同步；后续相对最后一次成功同步达到 2 分钟或移动 250 米时同步。
- [ ] 时间与距离为“或”关系，只用于筛选系统已交付的位置事件；App 不使用自建定时器承诺严格周期。
- [ ] 用户明确选择模式并在申请权限前理解功耗差异；0.2 不提供自定义阈值。
- [ ] 手动模式只需使用期间定位权限；自动模式需要始终定位权限，权限不足时不得显示为正在后台运行，并提供恢复路径。
- [ ] 自动模式始终提供可见的停止开关；停止、模式切换或权限失效会取消定位、退避、连接和发送任务。
- [ ] App 离开盒子局域网后暂停连接和发送，不进行高频失败重试；离网期间只在内存中覆盖保留最新有效位置，不持久化精确坐标。
- [ ] 用户未主动停止且权限仍满足时，恢复局域网后 App 重新连接并立即尝试发送最新有效位置；App 重启后等待新的有效位置事件。
- [ ] App 持久化用户选择的模式，但不持久化精确坐标；系统允许后台重新启动时恢复相应定位会话。
- [ ] App 分别显示后台定位授权、运行/暂停原因、最后一次尝试及最后一次成功，不把失败表述为已同步。

#### SPEC-005：官方 Web 后台入口

**优先级：** Should
**状态：** Approved

App 应使用系统标准 `SFSafariViewController` 打开所选盒子的官方后台及 QSO 页面，不注入脚本模拟未公开接口。

**验收标准：**

- [ ] “管理后台”使用所选设备的稳定 HTTP 端点打开 `/`，“QSO 页面”打开 `/qso.html`。
- [ ] 未选择设备、端点无效或页面不可达时显示可行动错误，不构造或加载任意外部地址。
- [ ] App 不注入 JavaScript、不读取或模拟 DOM、不调用未公开接口；需要完整 Safari 时使用系统浏览器提供的标准操作。
- [ ] URL 构造具有确定性单元测试，两个入口分别具有界面覆盖。

#### SPEC-014：设备仪表盘与锁屏实时活动

**优先级：** Must
**状态：** Approved

App 应在连接 FMO 后，用同一份类型化状态快照驱动首页设备仪表盘与用户主动开启的锁屏实时活动。原型以 0.3 已确认的字段语义为准；正式 App 按字段渐进接入，只有具备公开文档、接口所有者明确授权或经 ADR 批准来源的字段才可开发为可用状态。原型示例值和抓包观察本身不得作为 Release 授权的证明。

**首页信息：**

- 大字号我的呼号、过滤器距离，以及由 WGS84 坐标派生的六位梅登黑德网格；首页不显示经纬度。
- 当前连接服务器名称；服务器 UID 只用于内部关联。管理员呼号只有取得可靠字段时才条件显示。
- 单行动态事件窗口显示当前讲话呼号、可选网格与最近本地活动；当前讲话优先固定，结束后恢复纵向事件切换。本地事件与 0.4 APRS `VOCAL` 时间线是不同来源。
- 单一工作频率与盒子报告的 QSO 日志数保留在类型化数据层或对应功能页，不投影到首页仪表盘；不得拆成 TX/RX，也不得把日志数表述为实时通联人数。
- 延迟、服务器管理员呼号和当前/最大在线人数在 0.3 隐藏，取得可靠来源后另行评审。

**验收标准：**

- [ ] 首页完整仪表盘与锁屏精简仪表盘由同一个 `DashboardSnapshot` 投影，公共字段的值、来源、观测时间和过期状态一致。
- [ ] 每个字段具有“可用、未知、过期、不支持或已拒绝”的明确状态；单个来源失败只降级相关字段，不把未知值显示成 `0` 或实时数据。
- [x] HTML 原型覆盖 0.3 已确认的信息层级；ADR-0005 白名单字段已进入正式 App，白名单外字段继续不渲染或保持 `unknown / unsupported`。
- [ ] Release composition 不注入原型或 Preview 数据提供者；自动测试证明正式路径不存在硬编码示例值或模拟回退。
- [x] “我的呼号”“当前服务器”“过滤距离”和“当前讲话者”只来自 ADR-0005 类型化白名单，不使用 APRS、BEACON、导入 QSO 或 GEO RTT 冒充；数据层保留的频率和 QSO 日志数遵循同一来源边界，但不投影到首页。
- [x] 过滤原始枚举 `0...7` 分别映射为禁用、50、100、200、500、1000、2000、5000 km；未知值拒绝。
- [x] 梅登黑德网格只由带来源、观测时间的有效 WGS84 坐标派生，并继承坐标的可信度与过期状态。
- [x] 本地 `/events qso/callsign` 只有在事件流健康且状态新鲜时才表述为当前讲话者；讲话结束、断流或过期时立即清除。图标辅助功能语义为“当前讲话”，可选 grid 缺失只降级位置。
- [x] 本地 `/events qso/history` 只作为最多 20 条近期设备活动，与 APRS `VOCAL`、完整 QSO 数据库分开建模；首页最多投影最新一条，锁屏投影待 ActivityKit 实现。
- [ ] 锁屏默认仅显示连接状态、呼号、当前服务器、最新一条本地活动和更新时间；不显示频率、日志列表、过滤距离、延迟、在线人数或精确位置。
- [ ] 用户主动开始和结束锁屏仪表盘；连接中断时保留最后可信快照并明确显示“已过期/最后更新”，不伪装为仍在线。
- [ ] 实时活动不可用、启动失败、被系统结束或超过系统生命周期时，不影响首页仪表盘与设备连接。
- [ ] 呼号和位置类信息具有独立的锁屏隐私开关；梅登黑德坐标默认不在锁屏显示。
- [ ] 实时活动扩展不自行联网或定位；0.3 只由 App 进行尽力而为的本地更新，不承诺锁屏后台持续实时刷新。
- [ ] 锁屏只携带当前确有可信来源的字段，不为保持原型版式而编码 `unsupported` 字段或示例值。
- [ ] ActivityKit 静态与动态数据合计保持在 4 KB 以内，设置合理 `staleDate`，并按系统约束验收最长 8 小时活动期及其后最多 4 小时锁屏保留期。
- [ ] 不读取官方 Web DOM、不注入脚本；未获公开文档、接口所有者授权或边界 ADR 批准的管理接口不得进入 Release，也不通过 APRS 推断缺失的设备内部实时状态。

### APRS 网络

#### SPEC-006：FMO V4 地图与台站目录

**优先级：** Must
**状态：** Approved

App 应展示通过 FMO V4 APRS 获得的用户、BEACON 与 STATION 信息，包括位置、呼号、服务器地址、覆盖范围、在线/峰值人数和数据年龄。

**验收标准：**

- [ ] 用户可分别收藏呼号与公共 FMO 服务器；呼号按规范化基础呼号去重，服务器按已验证稳定 UID 去重，名称、地址或端口变化不产生重复收藏。
- [ ] 收藏状态本地持久化并与短期 APRS 缓存分离；刷新、离线、数据过期和 App 重启不会静默移除收藏。
- [ ] 取消收藏只移除可逆偏好，不删除目录对象、历史事件、QSO 或信任材料，也不需要危险确认。
- [ ] 收藏状态不改变可信度；已收藏对象过期、吊销或无法验证时仍显示其真实信任状态。
- [ ] “收藏呼号”作为 0.6 消息页的常用联系人来源，不额外维护一套含糊的联系人收藏；收藏公共服务器不与 SPEC-012 自建管理服务器共用身份。

#### SPEC-007：事件时间线与通知

**优先级：** Should
**状态：** Approved

App 应支持 `CQ`、`OMCQ`、`VOCAL`、`ONLINE`、`BEACON`、`STATION` 与 `JOINT + EVENT`，并允许按类型、呼号、距离和收藏过滤。

**验收标准：**

- [ ] “收藏”过滤同时匹配事件主体的收藏呼号与事件关联的收藏服务器；无收藏时显示可行动空状态。
- [ ] 完整验证的 `VOCAL` 只生成带呼号、SSID、位置、服务器 UID、观测时间与可信状态的“最近语音活动”事件，不生成“当前通联对象”或“当前说话人”。
- [ ] `CQ` / `OMCQ` 只表述为发起呼叫，不推断呼叫目标、接听结果或已建立通联；QSO 历史不进入实时事件状态。
- [ ] 语音事件可以用扬声器或对讲机图标压缩可见文案，但必须同时保留呼号、观测时间及可访问性标签；不能只靠颜色表达。
- [ ] 多个近期 `VOCAL` 按可信观测时间排序，主界面显示最新一条并保留其他数量或入口；验签失败、重放、乱序旧帧不得覆盖更新的可信事件。
- [ ] `VOCAL` 没有结束事件；产品定义的近期展示窗口独立于 `timeSalt` 验证窗口，过期后只能表述为“最后活动于”，不能断言讲话已经结束。

#### SPEC-008：FMO V4 身份验证

**优先级：** Must
**状态：** Approved

App 应验证 CERT blob、呼号绑定、证书链、证书有效期、Ed25519 消息签名、timeSalt 窗口、JOINT/EVENT 哈希关系和可用 CRL。

**验收标准：**

- [ ] 无法验证的数据不得显示为“可信”。
- [ ] 过期、吊销、签名错误、呼号不匹配和未知根具有不同状态。
- [ ] 不通过降低验证强度来兼容错误报文。

#### SPEC-009：APRS 短消息

**优先级：** Should
**状态：** Approved

用户可配置自己的呼号、SSID 和 APRS PASSCODE，发送/接收标准 APRS 消息与 ACK。凭据必须保存到 Keychain。

#### SPEC-010：FMO 远程控制

**优先级：** Must
**状态：** Approved

App 应按官方示例生成 `NORMAL`、`STANDBY`、`REBOOT`，实现 Time Slot、Counter、HMAC-SHA1 截断签名和 ACK 等待。

**验收标准：**

- [ ] 远控 SECRET 和 PASSCODE 不写入日志或服务器。
- [ ] `REBOOT` 必须经过 LocalAuthentication 二次确认。
- [ ] Counter 在同一 Time Slot 内单调递增并持久化，避免 App 重启后重放。

### QSO 与服务器

#### SPEC-011：QSO 导入、查询与 ADIF

**优先级：** Should
**状态：** Approved

App 应读取用户从 `qso.html` 主动下载的 SQLite 数据库，支持查询、地图、SHA-256 完整性、ECDSA P-256 验签与 ADIF 导出。

#### SPEC-012：自建服务器运维

**优先级：** Could
**状态：** Approved

App 应通过独立 HTTPS API 查看自建服务器的 DNS、MQTT 可达性、EMQX/SAS 状态、连接数、资源使用、广播状态和脱敏日志。写操作必须单独授权并二次确认。

#### SPEC-013：iOS 系统集成

**优先级：** Could
**状态：** Approved

支持 APNs、本地通知、桌面小组件、Siri 快捷指令、深色模式、动态字体和 VoiceOver。设备锁屏实时活动由 SPEC-014 单独定义；普通锁屏小组件仍属于后续系统集成范围。

## 明确排除

- 解码或收发 FMO MQTT 语音。
- 模拟盒子登录 MQTT。
- 获取、导出、复制或使用盒子私钥。
- 逆向未公开的盒子配置、服务器切换、音量、频率、编码器或 OTA 接口。
- App 内完成官方设备激活或证书签发。
- 将 iPhone 个人热点拓扑列为保证能力，除非实机验证通过。
