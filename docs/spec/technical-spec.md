# 技术规格

## 平台与兼容性

- 最低系统：iOS 26.0；不为 iOS 18 及更早版本维护兼容分支。
- API 策略：可直接使用 iOS 26 API，不主动添加旧系统 availability 分支或兼容垫片。
- 开发工具：Xcode 26.6；工程格式由 Xcode 管理。
- UI：SwiftUI，支持 iPhone；iPad 自适应作为非阻塞兼容目标。
- 并发：Swift Concurrency，避免新增长生命周期的裸线程或回调金字塔。
- 持久化：普通设置使用轻量本地存储；结构化 App 数据使用 SwiftData；导入 FMO QSO 数据库时只读访问 SQLite。

## 模块边界

- `Device`：发现、保存设备、连接诊断。
- `Location`：Core Location、节流策略、坐标同步。
- `APRS`：传输、解析、证书与签名验证、地图模型。
- `RemoteControl`：命令计数器、签名、发送与 ACK。
- `QSO`：文件导入、SQLite、验签、ADIF。
- `Server`：自建 HTTPS API 客户端。
- `Core`：共享网络、安全、持久化、时间与诊断抽象。

UI 不直接依赖具体网络或加密实现；Feature 通过协议依赖 Core 服务。

## 网络

- Bonjour 使用 Network.framework，浏览 `_http._tcp` 并解析端点。
- GEO 使用 `URLSessionWebSocketTask`，地址为 `ws://<host>/ws`。
- 默认单次业务响应超时 5 秒，发现超时 10 秒；超时作为可测试策略注入。
- WebSocket 应支持取消、重连退避与 App 生命周期变化。
- HTTP 明文仅允许局域网官方后台/GEO 的必要范围，不设置全局任意网络放行。
- 自建服务器 API 必须使用 HTTPS 443 和短时认证令牌。

## 定位与后台执行

- 权限按需请求，先解释用途再触发系统弹窗。
- 精确坐标默认只用于同步，不上传到分析服务。
- 后台工作由 Core Location 允许的事件驱动；时间/距离阈值只做节流。
- 连接不可用时停止高频发送，保存有限诊断状态并等待网络恢复。
- 个人热点反向访问必须作为独立测试矩阵，不从普通 Wi-Fi 结果推断。

## 安全与隐私

- APRS PASSCODE、远控 SECRET、服务器令牌进入 Keychain。
- P-256 和 SHA-256 优先使用 CryptoKit。
- Ed25519、CBOR 仅在 Apple API 不满足确定性编码要求时引入审计过的最小依赖。
- 根证书和中间证书是公开信任材料，可随 App 分发；私钥不得进入仓库或 App。
- 验证顺序：解析 → 呼号绑定 → 证书链 → 有效期 → CRL → 消息签名 → 重放窗口 → 业务处理。
- 导入 QSO 文件采用安全作用域文件访问或复制到 App 沙箱；不修改原始文件。
- 诊断日志默认脱敏，用户主动导出前再次预览。

## 性能目标

- 正常局域网下，设备发现结果或超时反馈不超过 10 秒。
- GEO 操作业务超时默认 5 秒。
- APRS 地图数据解析不阻塞 MainActor。
- 10,000 条 QSO 记录的首次导入和索引在现代 iPhone 上保持可取消，并提供进度反馈。
- 后台定位模式必须提供功耗说明和可见的停止开关。

## 可靠性

- 任何外部报文都视为不可信输入，解析器必须有长度、范围和格式检查。
- 网络错误使用类型化错误，不以字符串匹配驱动业务逻辑。
- 协议解析器、签名验证器、计数器和坐标节流器使用确定性单元测试。
- 所有真实时间、随机数、网络和位置来源均应可注入测试替身。
- 远控 Counter 在同一 Time Slot 中持久化，状态写入必须原子化。

## 测试策略

- Swift Testing：模型、协议编解码、错误映射、安全边界。
- URLProtocol/传输替身：HTTP 与 WebSocket 状态机。
- XCUITest：首次权限说明、手动 IP、坐标同步主流程、危险操作确认。
- 真机：Bonjour、本地网络权限、后台定位、普通 Wi-Fi、便携路由器、iPhone 个人热点。
- 固定官方报文向量：APRS CBOR、签名、QSO 验签；测试数据不得包含真实秘密。

## 依赖策略

1. 优先 Apple 平台框架。
2. 新依赖必须说明用途、许可证、维护状态、可替代方案和移除成本。
3. 添加或升级依赖属于架构影响，必须更新本文件和必要 ADR。
4. 不引入仅为简化少量代码的大型框架。
