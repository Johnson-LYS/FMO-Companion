# 计划 0010：触觉反馈

## 目标

用克制且可预测的 iPhone 触觉补充关键交互结果，让用户在不持续注视屏幕时也能区分操作完成、结果不确定、明确失败，以及本地讲话开始和结束。

## 触觉语言

| 场景 | 反馈 |
|---|---|
| 用户主动任务已确认完成 | `success` |
| 结果部分完成或未确认 | `warning` |
| 用户主动任务明确失败 | `error` |
| 轻量选项或开关改变 | `selection` |
| 讲话开始 | 中等 `impact` |
| 讲话结束 | 轻量 `impact` |

## 首轮范围

- 坐标同步、手动设备连接、服务器切换、APRS 消息 ACK、远控确认/未确认、QSO 手动刷新与 ADIF 准备结果使用对应的语义反馈。
- 声音、地图/方位盘、地图追踪和外观等直接选择使用轻量反馈；删除或停止等明确执行动作只反馈一次。
- 本地 `/events qso/callsign` 的真实讲话开始使用中等触感，真实讲话结束使用轻触感。相同讲话者的重复状态不反馈；说话人直接变化只反馈新讲话开始；短间隔的结束后开始合并，避免连续双震。
- “设置 → 触觉”提供独立“讲话触觉”开关，默认开启并持久化；它不与设备声音开关绑定。

## 抑制规则

- 讲话触觉只在 App 前台且设备页或横屏仪表盘可见时触发；后台不以应用内触觉模拟通知。
- 事件流断开、设备断线或字段过期不冒充讲话结束。
- Bonjour 发现、自动恢复连接、WebSocket 重连、后台位置同步、QSO 自动同步、APRS 帧、波形、地图位置与加载进度不触发触觉。
- 触觉只由状态边沿变化触发；视图重建、重复赋值、冷启动恢复已有状态不得重复触发。
- 使用系统语义化触觉并尊重 iOS 系统设置；除“讲话触觉”外不增加全局触觉总开关。

## 验收标准

- [ ] 讲话开始与结束具有可区分的触感，相同状态不重复触发。
- [ ] 说话人直接切换或短时间“结束 → 新开始”不会产生结束与开始的连续双震。
- [ ] 关闭“讲话触觉”后不再产生讲话反馈，但其他用户主动操作反馈不受影响。
- [x] 后台、其他标签、事件断流与自动任务不会产生讲话触觉。
- [x] 关键操作的成功、未确认和失败语义与页面最终状态一致，不把超时未确认误报为明确失败。
- [x] 纯策略单元测试覆盖讲话状态边沿、切换、断流和可见性门控；相关界面仍需在真机完成触感强度验收。
