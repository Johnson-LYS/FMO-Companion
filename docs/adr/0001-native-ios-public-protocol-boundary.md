# 0001：原生 iOS 与公开协议边界

**日期：** 2026-08-03
**状态：** Accepted；由 ADR-0005、ADR-0009 作有限修订；MQTT 语音排除条款由 ADR-0011 取代

## 背景

FMO 的局域网 GEO 接口、V4 APRS 报文、APRS 远控和若干日志工具已经公开，但核心终端固件、MQTT 语音帧、编码器和设备私钥没有作为完整客户端 SDK 开放。用户希望手机与 FMO 同局域网时获得更好的原生体验，同时不采用 Hack 手段。

## 考虑的方案

1. **原生 iOS + 公开接口**：SwiftUI、Bonjour、GEO WebSocket、APRS 和用户导出文件。
2. **Web/PWA**：开发较快，但后台定位、Bonjour、本地网络权限和 Keychain 体验较弱。
3. **逆向完整客户端**：尝试还原 MQTT 语音与设备身份，风险高且违背项目边界。

## 决策

选择原生 iOS，并把公开接口边界作为产品和安全约束。未公开设置通过官方 Web UI 打开；未公开语音与设备身份功能不进入开发范围，除非未来出现正式文档、SDK 或授权方式。2026-08-05 起，ADR-0005 仅对用户授权的本地只读设备状态作最小例外；2026-08-11 起，ADR-0009 再对用户确认的固定本地 `/audio` PCM 只接收契约作隔离、前台且不落盘的最小例外。其他写操作、秘密和音频协议仍保持本决策边界。

## 后果

### 正面

- 可可靠使用 iOS 本地网络、后台定位、Keychain、通知和快捷指令。
- 不依赖设备私钥提取或脆弱的逆向协议。
- 产品范围可以用公开文档和固定测试向量验证。

### 负面

- 本决策形成时，App 只能在 ADR-0009 的固定本地只接收契约内播放设备音频；该限制后来由 ADR-0011 对“App 独立身份 + 官方公开语音协议”作定向取代，盒子私钥和未公开协议边界不变。
- 一些盒子设置只能打开官方 Web UI，无法提供完全原生的配置体验。
- APRS 和证书协议升级时需要同步维护解析与信任材料。

### 中性

- 自建服务器运维需要单独开发 HTTPS API，不属于 FMO 盒子协议。
