# 计划 0006：里程碑 0.3 设备仪表盘基础

## 目标

交付接近盒子屏幕、并与已确认字段语义一致的首页仪表盘，同时实现共享状态模型、局部降级和来源门槛已经满足的字段。ADR-0005 已批准用户授权的本地只读状态白名单；0.3 按该边界进入 Release 实现。实时活动自 2026-08-05 起从 0.3 范围移除，现有 ActivityKit 探索实现只作为后续 checkpoint，不提供用户入口，也不计入 0.3 完成度。

## 范围门槛

1. 首页卡内容于 2026-08-05 收敛为“我的 FMO、当前服务器、单行动态事件”三块；独立视觉稿确认后同步首页投影。
2. 0.3 可基于现有 GEO 接口开发共享模型、本地会话状态、坐标派生 Maidenhead 和局部降级。
3. 每个新增设备内部字段必须先取得公开契约、接口所有者授权，或像 ADR-0005 一样由用户授权并固定严格最小边界，明确传输、鉴权、字段、单位、更新时间、错误与版本策略。
4. 无正式来源的字段登记为 `Deferred — external contract`，不进入 Release 的 `available` 状态，不用 APRS、QSO 导入、GEO RTT 或 fixture 冒充。
5. 超出 ADR-0005 白名单的抓包观察仍登记为 `Observed — authorization pending`，不能因同一端点已接入而扩大开发范围。

完整设备状态接口仍是完整仪表盘数据的门槛，但不再作为基础状态模型和 GEO 支持字段的总里程碑门槛。

## 状态模型

- `DashboardSnapshot` 是首页仪表盘的唯一规范输入。
- 每个字段包含值、来源、`observedAt`、可信度以及 `available / unknown / stale / unsupported / rejected` 状态。
- GEO、本地设备状态和未来 APRS 连接互相独立；单一来源失败只降级相关字段。
- 连接中断保留最后可信值并显示最后更新时间；不会把缓存值写成“实时”。
- 本地 `/events qso/callsign` 独立提供有开始/空闲状态的当前讲话者；它不能与 APRS `VOCAL` 的“最近检测到语音活动”模型合并。可见界面优先用扬声器图标、呼号、可选网格和时间表达，不堆叠重复文案。
- 事件行只有在规范化呼号变化时执行整行纵向切换；同一呼号讲话结束时只替换图标并平滑置灰呼号，相对时间每秒刷新。
- Release 依赖组合不包含 demo provider；fixture 只存在于测试、Preview 与 HTML 原型。

## 用户流程

1. App 启动自动扫描，并按 SPEC-001 的“上次成功、其余保存、新发现”顺序串行连接；任一设备成功后停止自动切换。
2. 未连接时，首页顶部卡片主操作打开设备选择 Sheet；扫描结果、手动地址和设备切换均在 Sheet 中完成。
3. 连接成功后，顶部卡片原位切换为仪表盘基础；呼号同一行右侧的设备按钮打开选择 Sheet，只呈现已有真实来源的字段。
4. 网络断开时，首页进入过期态并显示最后更新时间；恢复后由新快照刷新。
5. 首页和卡片均不提供主动断开入口。

## 实施顺序

完成记录（2026-08-06）：共享快照、三条独立链路状态、GEO/Maidenhead、ADR-0005 `/ws` 状态客户端、连接期间的当前服务器只读刷新、`/events` 事件流、三段式首页投影，以及“恢复上次设备 + 卡片设备按钮 + 设备选择 Sheet”原生 UX 均已实现并完成用户真机验收。完整 `FMOcTests` 在 iOS 26.5 Simulator 上通过 20 个套件、93 项测试；通用 Simulator 基线构建通过。UI 测试源码完成编译，但当前本机 Xcode UI runner 仍受 `DebuggerVersionStore: no debugger version` 环境问题影响，已有真机手动验收覆盖本里程碑核心交互。ActivityKit App 生命周期与 Widget Extension 只保留为探索 checkpoint，主 App target 已解除依赖和嵌入，不属于 0.3 Release composition。

2026-08-05 使用用户临时提供的可达地址进行脱敏最小探测：`/ws` 五个白名单请求全部返回预期路由和字段类型；`/events` 握手成功但 5 秒窗口内没有事件帧，因此事件值解码仍需在实际讲话/历史事件出现时完成真机验收。仓库不记录该地址，探测没有输出或保存真实字段值。

历史验证记录：App 与 `FMOcLiveActivity` Extension 的通用 Simulator 联合构建、相关单元测试曾通过，但连续真机验收未显示实时活动。因此该实现保留为后续诊断和设计 checkpoint，不作为 0.3 已交付能力。0.3 后续验证只覆盖首页仪表盘、启动恢复上次设备、选择 Sheet、手动切换、断线过期与恢复。

### 待补观察与真机验证

- [ ] 服务器不可达、恢复与 WebSocket 重连；不把“无服务器”发明成正常选择。
- [ ] `isHost: true` 样本；取得前隐藏主机/管理员角色。
- [ ] FMO 重启后 `/events seq/ts`；取得前重连后重新拉全量快照，不跨会话续排。
- [ ] 若未来发现在线/最大人数或管理员呼号的正式字段，再单独评审并接入。
- [x] 连接断开/恢复的首页过期刷新，以及切换设备后的旧状态隔离。
- [x] 真机在盒子上执行服务器 A → B → A，确认首页均在下一轮只读刷新后同步且不影响事件流。

### 1. 纯模型与延期字段登记

- 实现字段状态、可信度、来源和时间模型。
- 为每个目标字段登记当前来源或 `Deferred — external contract`。
- 用 fixture 覆盖完整、局部、过期、拒绝、长文本和边界值。

### 2. 状态聚合

- 通过协议注入现有 GEO 提供者、未来设备状态提供者、时钟和存储。
- Actor 隔离聚合，生成不可变 `DashboardSnapshot`。
- 确保断线、切换设备、取消和恢复不会串用旧设备状态。

### 3. 首页仪表盘

- 在现有连接卡片内呈现真实可用字段和局部降级。
- 延期字段按布局语义选择不渲染或明确不可用，不显示 `0`、`--` 或示例值冒充状态。
- 支持 Dynamic Type、VoiceOver、深色模式和窄屏布局。

### 4. ActivityKit checkpoint 隔离

- 0.3 用户界面不展示实时活动入口、状态或设置。
- 已有扩展与生命周期代码暂不继续打磨；主 App target 不依赖、不嵌入扩展，也不声明实时活动能力。支持类型只为 checkpoint 编译/测试保留，不进入运行时组合。
- 后续若恢复开发，先重新进入文档与原型评审，再决定是否复用现有 checkpoint。

### 5. 验证

- 单元测试：首页投影、局部降级、过期、切设备隔离及连接期间的当前服务器刷新。
- UI 测试：启动恢复上次设备、设备选择 Sheet、手动切换和断线过期态。
- 真机：首页信息、真实 FMO 状态/事件、启动恢复、切换与网络恢复。

## 不包含

- 未经官方文档、接口所有者授权或边界 ADR 批准的管理接口；网页 DOM 读取/注入、设备身份模拟或语音内容访问。
- 为填满仪表盘而前移完整 0.4 APRS 安全链或 0.8 QSO 导入。
- 0.3 中建设 APNs 推送后台或承诺锁屏持续实时刷新。
- 在锁屏携带精确坐标、完整事件数组、凭据或任何秘密。
- 任何实时活动、锁屏或 Dynamic Island 用户入口与交付承诺。
- 在 0.3 前移 0.4 的 APRS 接入、收藏呼号/公共服务器或收藏事件过滤；0.3 只为未来可信事件保留投影槽位。

## 0.3 基础完成定义

- SPEC-014 中共享模型、GEO 支持字段、局部降级与无模拟回退具有自动化或明确真机覆盖；外部契约字段保持延期登记。
- 首页快照的来源和过期状态不会误导用户。
- 启动优先恢复上一次成功连接的设备；设备选择 Sheet 支持扫描、手动地址和显式切换。
- 最终原型已经用户确认；Release 不含 fixture 或 demo provider，Simulator 构建及相关测试通过。
- 产品、技术、设计、模块文档和项目简报与实现一致。
- ADR-0005 字段计入 0.3 Release 完成度；白名单外字段继续按来源门槛延期。
