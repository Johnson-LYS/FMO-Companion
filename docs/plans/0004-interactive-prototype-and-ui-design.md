# 计划 0004：交互原型与 UI 设计基线

## 目标

在正式实施 0.1 产品代码前，以 HTML 验证 FMO Companion 的信息架构、核心任务流、视觉语言与后续 SwiftUI 实现约束。

## 交付

- `prototype/`：无需构建依赖的交互式 HTML 原型。
- `docs/design/ui-design-system.md`：色彩、排版、组件、状态、可访问性与 SwiftUI 映射规范。
- 0.1 核心闭环：权限说明、发现、手动回退、连接、读取/同步坐标、诊断。
- 全路线图原型：SPEC-001 至 SPEC-014 均有可点击入口、代表性状态和评审路径。
- `docs/design/prototype-coverage-matrix.md`：规格、原型入口和正式开发重点的映射。
- `docs/design/prototype-implementation-guide.md`：供后续 AI 将原型安全转换为 SwiftUI 的实现规则。

## 设计决策

- 主题色采用 `#FF8800`，用于主操作、选中态与关键强调。
- 用户层采用首页、FMO 网络、QSO、设置四个顶层区域。
- 远控归入设备，消息归入 FMO 网络，自建服务器归入设置中的管理员功能。
- 协议验证从台站详情按需展开，不在网络首页暴露密码学实现细节。
- 可见原型只呈现最终 App 用户界面，不显示规格编号、规划版本或评审工具。
- 规格覆盖、状态分支和 SwiftUI 映射集中记录在 AI 实现指南与覆盖矩阵中；网络、系统权限、密码学、文件与服务器操作均为模拟，不表示已经实现。
- 原型数据全部为虚构示例，且不访问真实网络、位置或凭据。

## 验证重点

- 用户是否理解连接状态与诊断层级。
- 自动发现失败时能否立即找到手动地址入口。
- 盒子坐标与 iPhone 坐标是否能被清楚区分。
- 橙色按钮、文本与深色模式是否保持足够对比度。
- 大字体、VoiceOver、减少动态效果与危险操作确认是否已进入正式实现要求。
