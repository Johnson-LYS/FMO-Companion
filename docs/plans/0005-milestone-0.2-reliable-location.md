# 计划 0005：里程碑 0.2 可靠定位

## 目标

在 0.1 单次坐标同步闭环之上，提供可理解、可停止、可恢复的自动定位同步，并通过系统标准浏览容器进入盒子官方管理与 QSO 页面。

## 范围

完整实现 SPEC-004 与 SPEC-005：

- 手动、低功耗、车载三种固定模式。
- Core Location 事件驱动的时间/距离节流。
- 始终定位授权、后台活动会话及系统重启恢复。
- 局域网路径门控、串行重连、可取消指数退避。
- 最后一次尝试、最后一次成功及暂停原因。
- 官方后台 `/` 与 QSO `/qso.html` 的 `SFSafariViewController` 入口。

不包含自定义阈值、严格定时调度、个人热点保证、自定义 WebView、DOM 注入或未公开设置接口。

## 已确认的行为契约

| 模式 | Core Location 配置 | 自动发送规则 | 权限 |
|---|---|---|---|
| 手动 | `.default` 单次更新 | 仅用户显式触发 | 使用期间 |
| 低功耗 | `.default` 持续事件 | 首次立即；后续 15 分钟或 1 公里 | 始终 |
| 车载 | `.automotiveNavigation` 持续事件 | 首次立即；后续 2 分钟或 250 米 | 始终 |

阈值基于最后一次成功同步。离网期间只在内存覆盖最新坐标；恢复后立即补发，App 重启后等待新事件。用户主动停止是最高优先级，不得被网络恢复或后台重启反向开启。

## 实施顺序

### 1. 纯领域模型

- `LocationSyncMode`：三种模式及固定预设。
- `LocationSyncPolicy`：首次、时间、距离、时间与距离、节流和手动判定。
- `LocationSyncSample`：带时间戳的有效坐标。
- 使用确定性单元测试覆盖阈值边界、OR 语义与距离计算。

### 2. 定位与权限适配

- 保留现有一次性 `PhoneLocationProviding`，避免破坏 0.1 手动流程。
- 新增可取消的自动位置事件协议和 Core Location 实现。
- 按模式持有 `CLServiceSession`、`CLBackgroundActivitySession` 与更新任务。
- 将授权和 Core Location diagnostics 映射为类型化运行状态。

### 3. 自动同步协调器

- 串联位置事件、节流、当前稳定端点、GEO 连接和发送。
- 对模式切换、停止、权限失效、并发位置事件和 App 生命周期执行结构化取消。
- 只在发送成功后推进节流检查点；失败保留最后尝试但不得覆盖最后成功。

### 4. 网络恢复

- 注入网络路径来源、时钟、等待器与退避策略。
- 离网不发起连接；恢复后合并为单一连接/发送任务。
- 路径可用但设备仍不可达时采用 1、2、4、8、16、30、60 秒退避，之后封顶 60 秒。

### 5. 界面

- 在设备页提供“位置自动化”入口，模式选择优先展示结果与功耗差异，不展示自定义滑块。
- 自动模式显示授权、运行/暂停原因、最后尝试、最后成功和明显的停止开关。
- 管理后台与 QSO 入口只在存在当前设备时可执行，并使用系统标准浏览器界面。
- 延续全行命中、系统原生列表手势及 `#FF8800` 主题规范。

### 6. 工程配置与验证

- 增加始终定位用途说明与 Location updates 后台模式。
- 单元测试：模式预设、节流边界、距离、权限状态、退避、取消、URL 构造及协调器状态机。
- UI/集成测试：权限说明、模式切换、停止、无设备 Web 入口、管理与 QSO 呈现。
- 真机：普通 Wi-Fi 和便携路由器的前后台、锁屏、离网、恢复、停止及系统终止恢复；个人热点单独记录，不作为完成门槛。
