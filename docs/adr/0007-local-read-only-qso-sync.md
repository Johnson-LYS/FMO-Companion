# 0007：采用 FMO 本地只读 QSO 自动同步

**日期：** 2026-08-08

**状态：** Accepted

**修订：** 扩展 ADR-0005，并取代其中“`qso/getList` 只读取 `count`、不得保存 QSO 内容”的限制

## 背景

0.8 原计划要求用户从 `qso.html` 手动下载 SQLite 和签名文件，再导入 App。用户明确确认：如果 QSO 不能从自己的 FMO 自动同步，这项功能没有保留价值。

2026-08-08 至 2026-08-09 对用户本人且由用户授权访问的 FMO 做了只读核对。设备官方 `qso.html` 通过同源 `/ws` 使用 `qso/getList` 分页读取摘要，并用 `qso/getDetail` 读取单条完整详情；无需 Cookie、Authorization 或 WebSocket 子协议。已确认列表响应位于 `data.list`，详情响应位于 `data.log`；摘要包含总数、分页、稳定 `logId`、时间、对端呼号与网格，详情包含双方呼号/网格、频率、模式、服务器名称、管理员呼号和备注。该接口仍没有公开版本、鉴权、TLS 和错误契约。

同一 QSO 管理界面还包含备份、恢复、清空、密钥重置、签名与 ADIF 生成等操作。将这些能力做成通用代理会突破 ADR-0001/0005 的最小授权边界，并增加误删除日志或暴露敏感字段的风险。

## 考虑的方案

1. **继续手动文件导入：** 契约最清晰，但无法满足用户确认的核心体验，0.8 将被取消。
2. **严格白名单的本地只读同步：** 只读取分页摘要与用户查看/导出所需详情，在前台自动同步并按设备缓存。
3. **自动触发完整数据库备份并验签：** 可复用 SQLite 工具链，但需调用未版本化 POST 导出流程，延迟和资源成本更高，也把日常浏览耦合到签名归档。
4. **复刻完整 QSO 管理后台：** 能力最多，但包含恢复、清空和密钥管理，不符合最小权限原则。

## 决策

采用方案 2，并以本 ADR 扩展 ADR-0005 的 QSO 边界：

- 新建独立、类型化的 `FmoQSOReadClient`，只公开 `list(page:pageSize:)` 与 `detail(logID:)`；底层不公开任意 `type/subType` 发送方法。
- 允许的请求仅为 `/ws` `qso/getList` 与 `qso/getDetail`；允许的响应字段采用固定 schema，未知字段丢弃。
- 明确禁止 `backup`、`restore`、`clearAll`、`getSign`、`getPublicKey`、`resetKeyPair`、ADIF 生成及任何其他 QSO/管理命令；不调用对应 HTTP POST/GET 导出流程。
- 自动同步只发生在用户所选 FMO 可达且 App 处于前台时：连接/切换设备、进入前台、打开 QSO 页面时触发；页面可见期间可以低频检查摘要变化，用户也可手动刷新。不得宣称后台实时同步或固定周期。
- 先分页同步全部摘要，以 `设备稳定身份 + logId` 作为缓存键并比较摘要指纹；详情按最近记录、用户打开和 ADIF 导出需求串行补齐。`/ws` 无请求 ID，所有 QSO 请求必须串行、可取消并隔离旧设备/旧会话响应。
- 设备离线时可以展示该设备最后一次完整成功同步的缓存并明确数据时间。完整分页同步成功后才执行删除对账；网络中断或部分同步不得删除既有缓存。
- 同步记录是“来自用户所选 FMO 的本地日志”，不得标记为经过数据库 P-256 验签。用户导出 SQLite、SHA-256/P-256 归档若未来保留，必须作为独立可选能力评审，不阻塞日常同步。
- 不记录原始帧、真实呼号、QSO 内容、网格、端点或备注；测试仅使用人工脱敏最小向量。

## 后果

### 正面

- QSO 成为连接 FMO 后自动可用的产品能力，不要求用户理解 SQLite、签名文件或文件导入。
- 类型化只读接口与管理/写操作隔离，符合用户授权与最小权限原则。
- 分页摘要优先、详情按需补齐，可在大日志量下尽快显示列表并控制设备负载。

### 负面

- 接口未版本化且使用明文局域网 WebSocket，固件变化可能使同步失效；解析必须失败关闭并回退离线缓存。
- 没有已确认的日志变更推送或版本令牌，前台只能在明确生命周期节点和页面可见时低频检查。
- WebSocket 逐条详情不具备完整 SQLite 快照签名的证明能力，不能沿用“已验证 QSO”文案。

### 中性

- 本决策不授权运行时抓包、DOM 注入、网页 Cookie 复制、任意管理命令、QSO 删除/恢复或设备密钥操作。
- FMO 官方 QSO 页面仍可通过 `SFSafariViewController` 打开，作为用户自行管理/备份盒子日志的独立入口。
