# 0009：采用用户授权的本地只接收 PCM 音频

**日期：** 2026-08-11

**状态：** Accepted

**修订：** ADR-0001 与 ADR-0005 的 `/audio` 排除条款

## 背景

用户希望在自己有权管理的 FMO 与 iPhone 位于同一局域网时，在设备横屏仪表盘查看实时音频波形，并可显式开启本机播放。用户提供并确认了固定本地契约：`ws://<selected-device>/audio` 只下发 8 kHz、16-bit signed little-endian、单声道 PCM；每个二进制消息固定 4480 字节，即 2240 个样本、0.28 秒；文本 `p` 是保活。

ADR-0001 原先排除未公开语音，ADR-0005 又把 `/audio` 永久排除在状态客户端之外。该边界可以避免通用协议代理、录音、设备模拟和私钥风险，但也阻止了用户明确授权的本地只接收监听。音频仍没有正式版本协商，因此只能以最小、失败关闭的固定契约接入。

## 考虑的方案

1. **继续完全排除 `/audio`：** 边界最简单，但不能满足横屏监听需求。
2. **独立的用户授权只接收 PCM 客户端：** 只接受固定 PCM 与保活，生命周期和数据处理受限，不修改状态客户端。
3. **实现通用音频/设备协议：** 自动探测格式、支持发送或还原其他语音链路，范围和安全风险不可接受。

## 决策

采用方案 2，并对 ADR-0001/0005 作有限修订：

- `/audio` 必须由独立 `FmoLocalAudioClient` 连接，不能加入 `FmoLocalStatusWebSocketClient`、通用 WebSocket 命令白名单或 Dashboard 状态快照。
- URL 只能从用户当前选择的稳定 FMO 端点构造；不硬编码 `fmo.local`、IP 或端口。
- 只接受精确文本 `p` 和长度恰为 4480 字节的二进制消息。PCM 固定为 8 kHz、signed Int16 little-endian、单声道。未知文本、错误长度或其他消息类型失败关闭。
- 客户端不发送业务消息，不请求麦克风权限，不实现音频上传、PTT、设备模拟、MQTT 音频或编码器。
- 音频只在 App active 且横屏仪表盘可见、所选设备未变化时接收。退出、后台、断线或切换设备立即取消 WebSocket、解码、播放和可视化任务。
- 每次进入横屏、恢复前台或切换设备均默认静音。静音时继续接收并更新波形；开启后只播放后续帧，不回放静音期间样本；关闭后立即停止输出。
- 原始 PCM 只存在于有界内存中，不录音、不持久化、不上传、不导出，不进入日志、诊断、分析、崩溃上下文、测试 fixture 或截图。
- PCM 与 `/events qso/callsign` 独立，不能用音频存在与否推断当前讲话者、呼号、通联对象或事件状态。
- 固件不兼容时失败关闭并隐藏/降级音频能力，不自动探测其他格式，也不扩大成本地通用音频代理。

## 后果

### 正面

- 用户可以在本人 FMO 的横屏仪表盘查看实时音频活动，并按需本地收听。
- 独立客户端和前台生命周期避免污染已验收的状态、事件、GEO 与 QSO 会话。
- 固定帧长度、格式与有界缓冲使协议异常和内存增长可测试。

### 负面

- 未版本化契约可能随固件变化，需要重新验证；App 不尝试兼容未知变体。
- 8 kHz、0.28 秒消息需要小型实时播放缓冲；网络抖动可能造成短暂欠载。
- 静音仍保持本地网络接收与波形计算，横屏使用期间会增加少量网络与能耗。

### 中性

- 该能力不改变 APRS、讲话事件、远控或设备身份边界。
- “设备音频”只描述字节来源，不承诺它等于接收端音频、当前讲话者音频或完整通联录音。
